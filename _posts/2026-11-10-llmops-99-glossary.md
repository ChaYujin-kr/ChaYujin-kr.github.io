| Rule of Two (1) | 한 경로에 [신뢰할 수 없는 입력 / 민감 데이터 / 외부 전송·실행] 셋이 동시에 있으면 안 된다는 설계 규칙 |

| 데이터/지시 분리 (3) | 질문과 문서를 태그 안에 넣고 "태그 안은 데이터"라고 명시하는 것 |
| 가드레일 (4) | 모델 앞뒤에서 입력·출력을 검사하고 고치는 코드 |
| 마스킹 (4) | 개인정보를 `[PHONE]` 같은 표시로 바꾸는 것 |

| 취약점 예외 (2) | 스캐너에서 특정 항목을 빼는 것. 사유와 만료일이 필수 |

| 추론 토큰 (5) | 답하기 전 모델이 내부적으로 생각하는 데 쓰는 토큰. 안 보이지만 비용은 나온다 |
| 구조화 출력 (3) | 모델이 정해진 JSON 모양으로만 답하게 강제하는 기능 |

| RAG (3) | 질문과 관련된 문서만 검색해 넣는 방식 |
| 프롬프트 캐시 (3) | 요청 앞부분이 이전과 같으면 제공사가 할인해 주는 것 |
| 앵커 (3) | URL의 `#` 뒷부분. 페이지 안의 해당 제목으로 바로 이동 |

| BM25 (9) | 질문 단어가 많이, 그리고 드물게 나오는 블록에 높은 점수를 주는 검색 공식 |
| prompt_cache_key (11) | 같은 키의 요청을 같은 캐시로 모으는 OpenAI 요청 값 |

## 평가

| 용어 | 뜻 |
|---|---|
| 정답 세트 (5) | 기대 결과를 미리 적어 둔 질문 모음 |
| LLM 채점 (5) | 더 큰 모델이 답을 채점하는 방식 (LLM-as-judge) |
| 근거 일치 (5) | 답의 주장이 인용한 단락에 실제로 있는가 |
| 거절 정확도 (5) | 답할 것엔 답하고, 범위 밖엔 "다루지 않아요"라고 했는가 |
| 기준선 (8) | 비교의 기준이 되는 이전 결과 |
| 회귀 (8) | 바꾼 뒤에 전보다 나빠지는 것 |
| 일관된 회귀 (8) | 기준선에선 매번 통과, 지금은 매번 실패. 흔들림과 구분하는 기준 |
| 429 / 레이트 리밋 (5) | 요청이 너무 많다는 응답. `Retry-After`로 기다릴 시간을 알려 준다 |

## Cloudflare

| 용어 | 뜻 |
|---|---|
| 게이트웨이 (0) | 브라우저와 AI 제공사 사이의 중간 서버. 키를 숨기고 제한을 건다 |
| Workers (6) | 요청이 올 때만 실행되는 작은 서버 코드. 서버 관리가 필요 없다 |
| workers.dev 서브도메인 (6) | 계정마다 하나인 주소 뒷부분. 주소 = `Worker이름.서브도메인.workers.dev` |
| wrangler (6) | Workers를 배포·관리하는 명령줄 도구 |
| 시크릿 (6) | 대시보드나 wrangler로만 넣는 비밀 값. 코드에 없다 |
| 서비스 바인딩 (6) | Worker끼리 인터넷을 거치지 않고 내부로 부르는 연결 |
| Durable Object (6) | Worker가 쓰는 작은 상태 저장소. 여기선 횟수 세기 |
| D1 (6) | Cloudflare의 SQLite 데이터베이스 |
| Cron 트리거 (6) | 정해진 시각에 Worker를 실행 (삭제·집계) |
| Turnstile (6) | 사람 확인(봇 차단). 대부분 클릭 없이 통과 |
| Access (7) | 주소 앞에 로그인을 세우는 Zero Trust 기능 |
| CORS (6) | 브라우저가 다른 사이트의 API를 부를 때의 허용 규칙. 서버 간 호출은 못 막아 보안 경계는 아니다 |
