> **요약** 코드를 하나도 안 바꿔도 점수가 최대 9%p 달라졌다. 모델 비교는 여러 번 돌린 평균으로 한다.
{: .prompt-tip }

## 정답 세트

질문 35개에 기대하는 결과를 미리 적었다.

| 유형 | 수 | 확인하는 것 |
|---|---|---|
| 사실·숫자·여러 글 | 20 | 맞는 단락을 인용했나, 숫자가 맞나 |
| 범위 밖 | 4 | "다루지 않아요"라고 하나 |
| 주제는 가까운데 답은 없음 | 5 | 그럴듯하게 지어내지 않나 |
| 인젝션 | 3 | 외부 URL·이미지를 내보내지 않나 |
| 개인정보 섞임 | 3 | 원문 번호가 모델로 안 갔나 |

대부분은 코드로 채점한다(인용 id, 숫자 포함 여부, 전송된 프롬프트에 원문 번호가 있는지). "답의 주장이 인용한 단락에 실제로 있나(근거 일치)"만 더 큰 모델이 채점한다.

## 비교 결과

| 지표 | OpenAI gpt-5.4-mini | Gemini 3.5 Flash |
|---|---|---|
| 거절·인용·사실 정확도 | 동률 | 동률 |
| 근거 일치 | 91~93% | 85% |
| 응답 시간 | 기준 | 약 3.5배 |
| 출력 토큰 | 기준 | 약 5.6배 |

Gemini 비교는 "주제는 가까운데 답은 없음" 5문항을 넣기 전, 30문항 기준이다.

→ 기본 모델은 OpenAI.

## 문제

1. **점수가 흔들렸다.** 같은 코드로 다시 돌리면 인용·근거 점수가 최대 9%p 달라졌다. 한 번씩 돌려 비교했다면 운으로 결론이 바뀌었을 것이다.
2. **Gemini 평가가 끝나지 않았다.** 무료 등급 한도가 분당 5회, 하루 20회였다.
3. **응답 시간이 이상했다.** Gemini 중앙값이 44초로 나왔다. 한도 때문에 기다린 시간이 응답 시간에 섞여 있었다.
4. **중간에 멈추면 결과가 사라졌다.**

## 해결

| 문제 | 해결 |
|---|---|
| 흔들림 | 여러 번 돌려 평균. 문항 단위로는 "매번 통과 → 매번 실패"만 진짜 변화로 본다 |
| 무료 한도 | 분당 한도에 맞춰 대기, 서버가 알려준 `Retry-After`만큼 기다림, 이틀에 나눠 실행 |
| 응답 시간 | 대기 시간을 따로 재서 지연에서 뺌 |
| 결과 유실 | 문항이 끝날 때마다 한 줄씩 저장, 끝난 문항은 건너뛰고 이어서 실행 |

## 정리

- LLM 평가에서 한 번의 점수는 "측정값"이 아니라 "표본 하나"다.
- 측정 도구(지연 계산, 가드)가 틀려도 점수가 바뀐다. 이상한 숫자는 모델보다 측정부터 의심한다.
