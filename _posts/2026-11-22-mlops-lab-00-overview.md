[6~7장 드리프트 실습]({% post_url 2026-11-08-mlops-drift-00-intro %})에 이어, 《Design a Machine Learning System (From Scratch)》의 7~11장을 실습했다. 시리즈의 11편부터 16편까지다. 앞의 절반(7~9장)은 신분증 사진에서 카드 위치를 찾는 객체 탐지, 뒤의 절반(10~11장)은 영화 추천이다. 둘 다 "데이터 준비 → 학습 → 검증 → 서빙" 순서를 Kubeflow Pipelines 위에서 밟는다.

이번에는 학습 모드가 아니라 실무 모드로 했다. 처음에는 직접 짜 보려 했는데 "컴포넌트", "아티팩트"라는 말부터 막혀서, AI가 전 과정을 돌리고 나는 결과와 기록을 읽는 쪽으로 바꿨다. 그래서 이 시리즈는 내가 푼 문제의 기록이라기보다 **돌려 보니 무슨 일이 있었는지의 기록**이다. 용어는 12편에 정리했다.

## 환경

| 항목 | 값 |
|---|---|
| 장비 | 노트북, WSL2, 메모리 7.7GB, GTX 1060 6GB |
| 클러스터 | kind (노드 1개), Kubeflow Pipelines, MinIO, MLflow 2.17.2 |
| SDK | kfp 2.9.0 |

메모리 7.7GB가 이번 실습의 가장 큰 제약이었다.

## 무엇을 돌렸나

| 편 | 장 | 한 일 | 결과 |
|---|---|---|---|
| 12 | 7 | 농담 파이프라인, 탐지 데이터 준비 | 성공. 이미지 570장을 427 / 85 / 58로 분할 |
| 13 | 8 | YOLOv8 학습·검증 파이프라인 | 다섯 번째에 성공. mAP50 0.995 |
| 14 | 9 | 탐지 모델 BentoML 서빙 | 코드 한 줄 고쳐 성공. 응답 0.2~0.4초 |
| 15 | 10 | 추천 데이터 준비, 학습·등록 파이프라인 | 여섯 번 중 두 번 성공. MLflow에 v1 등록 |
| 16 | 11 | 추천 서빙, 드리프트 감지, 설명 가능성 | 모두 동작. 내용은 다시 봐야 했음 |

파이프라인 실행만 세면 13번 제출해서 5번 성공했다.

## 멈춘 곳

실패 원인을 종류별로 묶으면 이렇다.

| 종류 | 사례 |
|---|---|
| 시간이 지나 바뀐 것 | Debian에서 없어진 `libgl1-mesa-glx`, 이름이 바뀐 `tojson()` |
| 기본값에 기댄 것 | `base_image` 생략 → SDK에 따라 Python 3.8 |
| 환경이 다른 것 | 저장은 Python 3.11, 읽기는 3.10 |
| 처음 또는 두 번째에만 깨지는 것 | 이미 있는 버킷, 아직 없는 스테이징 모델 |
| 자원 | 메모리 부족으로 WSL 재시작, `OOMKilled`, `pip` 시간 초과 |
| 단순 실수 | 같은 이름의 카운터 두 개, 없는 열 이름 |

3장 실습의 결론이 "2023년에 고정한 것이 지금은 깨진다"였는데, 여기서도 절반은 같은 이야기다.

## 멈추지 않은 곳

오류 없이 끝났지만 결과가 틀렸던 것이 네 가지 있다. 이번 실습에서 가장 남는 부분이다.

| 무엇이 | 겉보기 | 실제 |
|---|---|---|
| 탐지 데이터 분할 (12편) | 파이프라인 성공, 개수 맞음 | 검증 이미지 85장 중 71장의 라벨이 다른 묶음에 있음 |
| 추천 검증 지표 (15편) | rms 0.247 | 배치 평균끼리 비교한 값. 실제 오차는 약 0.94 |
| 추천 서빙 (16편) | 200 응답, 0.2초 | 추천 500개 중 실제 영화는 29개 |
| 드리프트 검사 (16편) | 점수 0.15 ~ 0.25 | 데이터가 같아도 시드가 다르면 0.25 |

넷 다 같은 방법으로 찾았다. **결과물을 원본과 대조하거나, 변화가 없는 대조군을 하나 더 돌렸다.** 로그나 상태 표시만 봐서는 찾을 수 없었다.

예상이 틀린 것도 있다. 라벨이 어긋난 데이터로 학습하면 모델이 나빠질 줄 알았는데 차이가 없었다. 망가진 쪽은 평가였다(13편). 같은 영상의 프레임이 학습과 검증에 섞여 점수가 부풀었을 것이라는 의심도, 영상 단위로 나눠 다시 재 보니 이 데이터에서는 근거가 없었다.

## 하지 않은 것

- 8장의 PVC(볼륨)를 쓰는 파이프라인은 돌리지 않았다.
- 9장, 11장의 서비스를 컨테이너 이미지로 만들어 클러스터에 올리지 않았다. 로컬에서 띄워 확인했다.
- 추천은 `ml-25m` 대신 `ml-latest-small`로, 30 에폭 대신 5 에폭으로 했다.
- 추천 서빙이 없는 영화를 추천하는 문제는 확인만 하고 고치지 않았다.

## 다음에 직접 해 볼 것

실무 모드로 지나온 만큼, 손으로 다시 해 볼 과제를 남긴다.

1. 농담 파이프라인의 `count_words` 컴포넌트를 보지 않고 다시 쓰기 (12편)
2. `OOMKilled`를 일부러 내고 `kubectl describe pod`에서 원인 찾기 (13편)
3. 드리프트 검사에 대조군 조건을 직접 추가하기 (16편)
4. 영화 ID를 빈틈없는 번호로 다시 매겨 추천 서빙 고치기 (16편)
