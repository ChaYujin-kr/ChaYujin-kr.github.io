> **요약** 정규식의 `\b`와 `\d`는 한글·전각 문자를 영어와 다르게 본다. 한국어 서비스라면 한국어 테스트 문장이 먼저다.
{: .prompt-tip }

## 가드 두 개

| 가드 | 언제 | 하는 일 |
|---|---|---|
| 입력 가림 | 모델에 보내기 **전**, 로그 저장 **전** (두 번) | 전화번호·이메일·카드번호·비밀번호 모양을 `[PHONE]` 등으로 |
| 출력 가드 | 화면에 보내기 전 | HTML 태그, 외부 URL, 마크다운 이미지·링크 제거 |

화면 쪽에서도 답을 `textContent`로만 넣는다. 가드가 놓쳐도 HTML로 실행되지 않는다.

## 문제 1: 조사가 붙은 번호

```text
010-1234-5678로 연락 주세요
```

이 번호가 가려지지 않았다. 패턴 끝을 `\b`(단어 경계)로 잡았는데, 파이썬에서 `\w`는 **한글도 단어 문자**로 본다. `8`과 `로` 사이가 경계가 아니게 된 것이다.

테스트용 가짜 번호였지만 실제로 두 모델에 전송됐고 로그에도 남았다.

## 문제 2: 부등호 사이를 지움

```text
p-value < 0.05, 거리 > 0.1이면 경보
```

출력 가드의 HTML 제거 규칙이 `<`부터 `>`까지를 태그로 보고 지웠다. 평가에서 채점 모델이 "근거 없음"이라고 한 답 중 일부는 모델이 아니라 **우리 가드가 문장을 망가뜨린 것**이었다.

## 문제 3: 전각 숫자, 붙어 있는 URL

- `０１０-１２３４-５６７８`(전각 숫자)은 `\d`에 안 걸리는 경우가 있었다.
- `참고https://...`처럼 한글에 붙은 URL이 지워지지 않았다.

## 해결

| 문제 | 해결 |
|---|---|
| 조사 붙은 번호 | 경계를 "ASCII 숫자가 아님"으로 명시 |
| 부등호 | 태그 **모양**(`<a ...>`, `</p>`)만 지움 |
| 전각 | 검사 전에 전각 → 반각 변환 |
| 붙은 URL | 앞 글자 조건을 "영문자가 아님"으로 |
| 이미 저장된 로그 | 다시 가리고 SQLite `VACUUM`(지운 내용이 파일에 남지 않게) |

## 어떻게 찾았나

문제 3은 파이썬 가드를 Cloudflare용 TypeScript로 옮기면서 찾았다. **같은 테스트 데이터 파일**을 두 언어 테스트가 함께 읽게 했더니 결과가 달랐고, 따라가 보니 원래 파이썬 쪽에 구멍이 있었다.

```text
tests/fixtures/core.json  ← 파이썬 테스트와 TypeScript 테스트가 같이 읽는다
```

이식이 곧 검증이 됐다. 지금도 가드를 고치면 이 파일에 문장을 먼저 추가한다.

## 정리

- 가드는 "모델이 알아서 하겠지"의 대체물이 아니라, 모델이 실패해도 피해가 없게 하는 마지막 층이다.
- 가드도 버그가 있다. 평가 점수가 이상하면 모델보다 우리 코드를 먼저 의심한다.
